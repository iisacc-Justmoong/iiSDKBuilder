# 독립 SDK 빌드 계획

빌드 manifest의 SDK 항목은 앱이 선택한 서로 독립적인 프로젝트이다. SDK 항목의
`depends`는 비어 있어야 하며 다른 SDK 이름이나 알 수 없는 이름이 있으면 계획을
거부한다. 기존 SDK 의존성 그래프와 자동 Core 선행 관계는 만들지 않는다. 앱은
`depends`로 선택한 여러 SDK를 명시할 수 있고 알 수 없는 이름은 거부한다.

기존 앱 빌드 계약을 위해 Core 프로젝트는 기본 선택 항목이다. 이후 SDK는 입력한
순서로 구성·빌드·설치하며 앱은 그 다음에 구성한다. 이 순서는 실행 순서이고 SDK
간 연결을 뜻하지 않는다. 각 SDK는 키트 prefix 아래 자신의 이름을 딴 설치 경로만
사용한다. SDK 구성의 검색 경로에는 자신의 경로와 호출자가 명시한 외부 경로만
전달하며 Core의 `iiSDKCore_DIR`를 자동으로 주입하지 않는다. 앱 구성은 모든 선택
SDK의 개별 설치 경로와 명시한 외부 경로를 함께 받는다. 계획 자체는 파일을 만들지 않는다.

기존 manifest의 SDK `depends`를 제거하고 각 SDK의 실제 코드·CMake·설치 패키지에서
다른 SDK 참조도 제거해야 한다. 앱 쪽의 명시적 패키지 검색과 연결은 유지한다.
이전 manifest는 새 도구에서 오류가 되므로 사용자와 CI 설정을 함께 이전해야 한다.
기존 공유 prefix의 패키지와 CMake 캐시를 보존하면서 새 `isolated/build` 경로를
사용한다. CMake가 설치 prefix를 시스템 검색 경로에 자동 추가하지 않도록 막는다.
호출자가 지정한 외부 경로와 플랫폼의 기본 검색 위치에는 다른 SDK가 있을 수 있고
모듈의 명시적인 검색을 이 계획만으로 막지는 못한다. SDK 전체의 정적 검사와 각
모듈의 다른 SDK 탐색을 끈 빌드·설치 소비자 검사를 별도로 수행한다.

빌더는 자식 CMake 구성·빌드·설치 명령에서 상속된 CMake 검색 경로, 컴파일러의
`CPATH` 계열·`LIBRARY_PATH`, pkg-config 경로와 동적 라이브러리 검색 경로를
비운다. 필요한 타깃 외부 패키지는 `prefixes`로, 필요한 환경값은 키트의
`environment`로 명시할 수 있으며 명시 환경은 상속값 제거 후 적용된다.
이는 프로세스 전체의 샌드박스가 아니다. 플랫폼 기본 경로와 `PATH`, Windows
컴파일러 초기화에 필요한 `INCLUDE`·`LIB` 및 호출자가 지정한 경로는 여전히
별도로 검토해야 한다.

이번 변경은 계획의 자동 연결과 선언을 제거하고 선택 SDK의 설치 경로를 분리한다.
한 SDK가 실패하면 그 SDK의 나머지 명령과 앱은 차단하고, 같은 키트의 다른 SDK는
계속 빌드한다. 하나라도 실패하면 키트와 전체 보고서는 실패이며 첫 SDK 오류를
보존한다. 취소는 이후 SDK와 앱도 차단한다.

iiSDKBuilder 라이브러리 자체는 아직 iiSDKCore와 iiFileProvider에 직접 의존하므로
별도로 이전해야 한다. 전체 SDK 독립화가 완료됐다는 뜻은 아니다. 기존 사용자 파일과
전역 설치본은 보존한다.

2026-10-28 macOS arm64에서 Core와 파일 제공자 설치본을 사용한 임시 빌드의
독립 프로젝트 계획·실제 CMake 조합·기존 계획·키트·명령·실패·취소·산출물
계약 검사·프로세스·임베디드 타깃 계약을 포함한 15/15가 통과했다. 실제 CMake
조합 검사는 다른 SDK 헤더가 들어 있는 상속 검색 환경에서 실패를 재현했고, 경로를
제거한 뒤 통과했다. 명시적 외부 경로를 따로 제공한 빌드도 기존 제한 시간으로
다시 실행해 통과했다. 실제 CMake 조합 검사는 서로 격리된 두 테스트 SDK를
설치하고 두 번째 SDK가 첫 번째 SDK를 발견하지 못하는지 확인한 뒤 앱이 둘을 함께
찾아 컴파일하는지 검사한다. 앱 산출물은 검사하지만 실행하지 않는다. 이는 빌더
본체의 독립 빌드나 다른 운영체제의 동작을 증명하지 않는다. 검사 실패는 비정상
종료 대신 실패 종료 코드와 진단으로 보고한다.
설치할 문서·예제·툴체인에서는 파일 제공자의 내부 프리뷰·잠금 정보와 `.DS_Store`를
제외하며 `tests/install_contents.py`로 임시 설치본의 내용을 검사한다.
