# Windows 라이브러리 판별 명세

Windows SDK의 `.lib`는 이름만으로 정적 아카이브와 DLL 가져오기 라이브러리를
구분할 수 없다. 빌더는 COFF 아카이브 멤버를 검사하여 실제 코드가 들어 있는
정적 라이브러리, DLL 가져오기 멤버, 두 종류의 혼합, 불명확하거나 손상된 파일을
구별한다. 혼합 라이브러리는 정적 코드를 포함하므로 정적 SDK 정책을 적용하며,
불명확한 형식은 동적이라고 추측하지 않고 오류로 보고한다. 이름·확장자·파일 내
임의 문자열만으로 동적 라이브러리라고 판정하지 않는다.

검사는 빌드된 SDK prefix의 실제 링크 입력에 적용한다. Windows SDK 외부의 시스템
라이브러리는 이 정책의 대상이 아니다. Microsoft COFF의 short import object는
서명, 버전, 기계형, 데이터 길이, 가져오기 심볼과 DLL 이름을 검증한다. 보통의
COFF 객체와 섹션 경계를 함께 확인하고, 정적 코드와 가져오기 항목이 섞인
아카이브도 허용 없이 통과시키지 않는다. 형식에 대한 증거가 불충분한 전통적
가져오기 아카이브는 추측 대신 오류로 남긴다.

테스트는 합성 아카이브의 경계·손상·혼합 사례와 Windows 대상 툴체인이 생성한
실제 정적·DLL 가져오기 아카이브를 비교한다. 검사 대상 앱은 실행하지 않는다.

하나의 CMake 링크 명령 조각에 여러 SDK 라이브러리 경로가 포함되더라도
각 파일을 따로 판별한다. 첫 번째 가져오기 라이브러리만 검사하고 뒤의 정적
라이브러리를 놓쳐서는 안 된다.
